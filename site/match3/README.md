# 果园消消乐 · 基础款

自研三消，无任何第三方依赖、无构建步骤。
目标：先把「传统三消的手感 + 基础规则」做扎实，再往上叠编程/规则卡那一层。

**玩：** `./dev.sh` → 打开 http://127.0.0.1:8150/

规则规格见 [RULES.md](RULES.md)（101 条断言与之一一对应）。

---

## 跑起来

```bash
cd basic
./dev.sh          # 起服务 + 自动开浏览器（默认 8150，可传端口：./dev.sh 8151）
node test/engine.test.js   # 引擎回归测试
```

> 需要 http 服务，不能直接双击 `index.html` —— 因为用了内联 SVG `<use>` 和 `fetch` 之外的浏览器安全限制；
> 更重要的是双击打开时 localStorage 的 origin 是 `file://`，存档行为不一致。

**为什么引擎/渲染分离**：引擎先把整个回合算完，输出步骤流；渲染层只负责"照着播"。
好处是引擎能在 node 里跑测试和 bot 模拟（关卡数值就是这么扫出来的），
不用开浏览器也能验证"4 连到底该不该出火箭"。

## 手感是怎么调的

这是这一版花时间最多的地方。几个具体决定：

| 决定 | 值 | 为什么 |
| --- | --- | --- |
| 交换时长 | 115ms | 再快就看不清发生了什么，再慢就"粘手" |
| 无效交换 | 交换 115 + 回弹 150 = 271ms 后可继续操作，抖动在后台播完 | 要有"我错了"的反馈，但不能因为反馈把玩家锁住 |
| 消除 → 开始下坠 | 只等 150ms | 不等动画播完。等播完会变成"一步一停" |
| 掉落时长 | `120 + 距离×26`，上限 300ms | 掉得远就久一点，但绝不超过 0.3 秒 |
| 落地 | 压扁 0.17s | 没有这个，掉落像"瞬移" |
| 连消提示 | 每层一个横幅 | ×2 不错 / ×3 很好 / ×4 太棒了 / ×5 无敌 |
| 新棋子 | 从棋盘外落进来 | 不从天上凭空出现，玩家能看懂"牌是从上面补的" |
| 道具发动 | 点一下就炸 | 造出来立刻能兑现，不用"再消一次"把爽点卡住 |

实测：普通一步 ≈ 596ms，无效交换 271ms 就放行，三层连消 ≈ 1.1s，点道具发动 ≈ 480ms（含整行清场 + 补牌）。

> **不要再加"过渡动画"**。三消的手感是「短、准、有重量」，不是「顺滑」。
> 每加 50ms，玩家就会开始怀疑自己点错了。

## 自动验收

```bash
node test/engine.test.js
```

覆盖：

1. 发牌（无三连 / 有解 / 同种子同棋盘）
2. 匹配检测（横 / 竖 / T 形合并 / 多组）
3. 特殊棋子判定（3/4/5 连、拐角、6 连）
4. 无效交换（还原 + 不扣步）
5. 三连（扣步 / 消除 / 计分 / 收集）
6. 四连 → 火箭（且在玩家动过的那格）
7. 五连 → 彩虹球（颜色变空、不参与三连）
8. 折角 → 炸弹
9. 彩虹球主动交换清色
10. 火箭被三连引爆清整行
11. 组合技（火箭×火箭、炸弹×炸弹、火箭×炸弹）
12. 重力与补充（无空洞）
13. 死局洗牌
14. 目标与星级
15. 8 关难度标定（两种玩家模型各 10 局）
16. **道具当场发动**：点一下 / 换一格 / 交换即瞄准 / 点普通棋子不算数

> 测试棋盘的构造原则：真实棋盘永远是"稳定"的（无三连），
> 所以所有图形都必须由**一次交换补上一个缺口**形成。第 5~8 组的构造都是这么写的。

## 下一步：把规则卡叠上来

现在 `specialFor(group)` 是硬编码：

```js
if (group.maxLen >= 5) return 'rainbow';
if (group.hasH && group.hasV) return 'bomb';
if (group.maxLen === 4) return group.dir === 'h' ? 'rocketH' : 'rocketV';
return null;
```

「规则卡」要做的事，就是把这四行变成一个玩家可编辑的表：

| 07 文档的概念 | 在这一版里的落点 |
| --- | --- |
| 规则表 = if/elif/else | `specialFor` 的四行分支 |
| 触发器 | `S.onEvent({type:'match', ...})` |
| 条件 | `group` 里已经有 color / shape / maxLen / dir / chain |
| 动作 | `spawn special` / `+分` / `变炸弹` |
| 顺序即玩法 | 分支顺序即优先级 |

所以接入点非常干净：**把 `specialFor` 从函数换成"查一组规则"，其它一行不用动。**

规则卡如果要加**新道具**（不只是换触发条件），第二个接入点是这两个纯函数：

```js
blastCells(S, cell)   // 道具 → 效果范围（一行 / 3×3 / 全场某色）
specialLabel(S, cell) // 道具 → 发动时飘出来的那行字
```

它们只读棋盘、不改状态，加一种"十字火箭"或"染色炸弹"只需要加一个 `case`，
不用碰主循环、不用碰渲染层 —— 渲染层已经在播 `blast` / `clear` / `fall` 三种通用步骤了。

> 四种道具的「点一下 / 换一格 / 被波及时」三条路径已经全部打通（RULES §5），
> 规则卡加上来的新道具会自动继承这三条路径 —— 这是先做基础款的收益。
